ОТО — диспетчеризация аэропорта
Запуск на Windows
=================

Что это
-------
Прототип диспетчерской ОТО с реальными картами Шереметьево и Домодедово,
2D- и 3D-видом, подбором ближайшего инженера по квалификации и допуску
на тип воздушного судна.

В этой версии есть два разных приложения:

  • Диспетчер  — http://127.0.0.1:8000/
  • Инженер    — http://127.0.0.1:8000/engineer

Вход выполняется по аккаунту. Роль «диспетчер/инженер» хранится на сервере,
а не выбирается в интерфейсе.

Быстрый запуск
--------------
1. Распакуйте архив в любую папку. Важно: не запускайте файлы прямо из ZIP —
   сначала извлеките папку полностью (правая кнопка → «Извлечь все»).
2. Установите Python 3.10 или новее: https://www.python.org/downloads/windows/
   При установке обязательно включите «Add python.exe to PATH».
3. Откройте папку проекта и дважды щёлкните файл:

       START-WINDOWS.bat

4. В чёрном окне выберите аэропорт:
       1 — Шереметьево (SVO)
       2 — Домодедово (DME)
5. Первый запуск создаст окружение .venv и скачает зависимости
   (FastAPI и Uvicorn). Для этого нужен интернет.
6. После запуска откроется страница входа:

       http://127.0.0.1:8000

7. Войдите под демо-аккаунтом (см. ниже) или зарегистрируйте инженера.

8. Чтобы остановить сервер, закройте окно с заголовком «OTO server» или
   нажмите Ctrl+C в этом окне.

Демо-аккаунты
-------------
Создаются при первом запуске автоматически.

  Диспетчер:
       email:  dispatcher@oto.ru
       пароль: Dispatcher2026!

  Инженеры (9 человек демо-смены):
       email:  tech1@oto.ru … tech9@oto.ru
       пароль: Engineer2026!

  Пример для инженера №1:
       tech1@oto.ru / Engineer2026!

После входа диспетчер попадает на карту, инженер — в личное мобильное
приложение.

Регистрация нового инженера
---------------------------
1. Откройте http://127.0.0.1:8000/login
2. Выберите «Регистрация инженера».
3. Заполните имя, email, пароль (минимум 8 символов), квалификацию,
   базу и допуски на типы ВС.
4. Нажмите «Отправить заявку». Войти сразу нельзя — заявка ждёт проверки.
5. Диспетчер входит на http://127.0.0.1:8000/
6. Открывает вкладку «Техники» и нажимает «Допустить» у заявки.
7. Инженер входит под своим email и попадает в /engineer.

После подтверждения инженер получает постоянный ID (начиная с 10) и
остаётся в смене после перезапуска сервера. Сброс демо-данных в интерфейсе
диспетчера очищает заявки и журнал, но не удаляет аккаунты.

Второй и последующие запуски
----------------------------
Зависимости уже установлены, поэтому запуск занимает несколько секунд.
Снова запустите START-WINDOWS.bat и выберите аэропорт.

Ручной запуск через PowerShell
------------------------------
Если автоматический файл не сработал, откройте PowerShell в папке проекта
(Shift + правая кнопка мыши → «Открыть окно PowerShell здесь») и выполните:

    py -3 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    python -m pip install -r requirements.txt
    python run.py --airport data\airport_sheremetyevo.json

Для Домодедово:

    python run.py --airport data\airport_domodedovo.json

Если PowerShell запрещает активацию окружения, выполните для текущего окна:

    Set-ExecutionPolicy -Scope Process Bypass

Затем снова:

    .\.venv\Scripts\Activate.ps1

Или запускайте Python напрямую без активации:

    .\.venv\Scripts\python.exe run.py --airport data\airport_sheremetyevo.json

Закрытый контур без демо-аккаунтов
----------------------------------
По умолчанию включён DEMO_MODE=1: создаются демо-диспетчер и девять
инженеров, а их логины показываются на странице входа.

Для пилота в закрытом контуре отключите демо-аккаунты и задайте первого
диспетчера через переменные окружения. В PowerShell:

    $env:DEMO_MODE="0"
    $env:DISPATCHER_EMAIL="dispatcher@example.ru"
    $env:DISPATCHER_PASSWORD="замените-на-сильный-пароль"
    $env:COOKIE_SECURE="1"
    .\.venv\Scripts\python.exe run.py --airport data\airport_sheremetyevo.json

COOKIE_SECURE=1 включает cookie только для HTTPS. Для локального HTTP
оставьте COOKIE_SECURE=0.

Регистрация инженеров в этом режиме продолжает работать: первый диспетчер
подтверждает заявки вручную.

Полезно знать
-------------
• Интерфейс работает локально, в интернет ничего не отправляется.
• Файл базы dispatch.db создаётся в папке проекта при первом запуске.
  В нём хранятся заявки, журнал, аккаунты и сессии.
• Пароли хранятся в виде PBKDF2-SHA256-хешей, сессии — в HttpOnly-cookie.
• Порт по умолчанию — 8000. Если он занят, запустите вручную, например:

      python run.py --airport data\airport_sheremetyevo.json --port 8001

  и откройте http://127.0.0.1:8001

• Кнопка «3D / 2D» находится в правом верхнем углу карты.
• Если Windows покажет запрос брандмауэра, для локального запуска доступ
  в интернет не нужен — можно нажать «Отмена».
• Карты: © участники OpenStreetMap, лицензия ODbL.

Если что-то не запускается
--------------------------
1. Проверьте, что Python установлен. В командной строке:

       py -3 --version

   Должна выводиться версия 3.10 или новее.

2. Если команда py не найдена, попробуйте:

       python --version

   Если открылся Microsoft Store — установите Python с python.org и включите
   «Add python.exe to PATH».

3. Удалите папку .venv и запустите START-WINDOWS.bat заново, если установка
   зависимостей прервалась.

4. Проверьте интернет при первом запуске: pip скачивает FastAPI и Uvicorn.

5. Если браузер открылся раньше сервера, просто обновите страницу через
   2–3 секунды.

6. Если забыли пароль демо-аккаунта, остановите сервер, удалите dispatch.db
   и запустите заново. Внимание: вместе с базой удалятся заявки и
   зарегистрированные аккаунты.

7. Если страница входа не открывается, проверьте окно «OTO server»:
   там должна быть строка Uvicorn running on http://127.0.0.1:8000.

Ограничения прототипа
---------------------
Это пилот, а не промышленная система. Нет подтверждения email,
восстановления пароля, 2FA и ограничения попыток входа. Для реальной
эксплуатации нужны HTTPS, корпоративный SSO или identity provider,
резервное копирование, аудит действий и rate limiting. SQLite рассчитан
на одну смену/площадку; для нескольких площадок нужна PostgreSQL.
