# Аэрофлот · Умная диспетчеризация ОТО

Прототип для конкурса: диспетчер видит борт, стоянку и свободных инженеров,
система выбирает подходящего техника с минимальным расчётным временем
прибытия, ведёт его по рулёжным дорожкам и считает норматив 15 минут. Инженер получает личное мобильное
приложение с заданием, маршрутом и отметками этапов.

Это уже не «одна страница с ролью в localStorage»: у приложения есть серверные
аккаунты, регистрация инженеров с подтверждением диспетчером, HttpOnly-сессии
и разделение данных по ролям.

## Роли и вход

| Роль | Адрес | Что доступно |
|---|---|---|
| Диспетчер | `/` | карта, рейсы, заявки, очередь регистрации, вся смена |
| Инженер | `/engineer` | только свои задания, маршрут, этапы, личная история |

После входа система сама перенаправляет на нужный интерфейс.

### Демо-аккаунты

Создаются при первом запуске, если `DEMO_MODE` не отключён.

| Роль | Email | Пароль |
|---|---|---|
| Диспетчер | `dispatcher@oto.ru` | `Dispatcher2026!` |
| Инженер №1 | `tech1@oto.ru` | `Engineer2026!` |
| … | … | … |
| Инженер №9 | `tech9@oto.ru` | `Engineer2026!` |

`tech1…tech9` соответствуют демо-смене из `data/technicians.json`.

### Регистрация инженера

1. Инженер открывает `/login` и выбирает **«Регистрация инженера»**.
2. Указывает имя, email, пароль, квалификацию, базу и допуски на типы ВС.
3. Заявка получает статус `pending`; войти до подтверждения нельзя.
4. Диспетчер открывает вкладку **«Техники»**, проверяет данные и нажимает
   **«Допустить»**.
5. Аккаунт получает постоянный `tech_id >= 10`, появляется в смене и может
   войти в `/engineer`. После перезапуска сервера техник восстанавливается
   из базы.

Отклонение заявки доступно там же, кнопкой **«Отклонить»**.

## Что внутри

- **Реальная авторизация**: SQLite-аккаунты, PBKDF2-SHA256-хеши паролей,
  серверные сессии в HttpOnly-cookie `oto_session` (7 дней), выход с удалением
  сессии.
- **Разделение данных**: диспетчер получает полное состояние; инженер — только
  свои заявки, историю и события. WebSocket тоже фильтруется по роли, а не
  просто отдаёт общий снапшот.
- **Реальные карты Шереметьево (SVO/UUEE) и Домодедово (DME/UUDD)** из
  OpenStreetMap: ВПП, рулёжные дорожки, перроны, терминалы, ангары и все
  места стоянок. Для симуляции выбираются 18 стоянок главного перрона.
- **2D-карта** (SVG) и **3D-вид** (canvas, без Three.js и внешних библиотек,
  чтобы работало офлайн и на слабых ТСД).
- **Подбор техника** по квалификации (`Планер`, `Двигатель`, `Авионика`),
  допуску на тип ВС, доступности, ETA и кратчайшему маршруту по графу.
- **Симуляция смены**: старт/пауза движения, изменение параметров специалиста,
  перенос свободных специалистов на узлы дорожной сети для контрольных сценариев.
- **Норматив 15 минут**, ЧС, очередь заявок, работа, устранение, журнал.
- **Приложение инженера**: mobile-first, крупные кнопки (от 44 px), мини-карта
  маршрута, автоматическое обновление по WebSocket, работа на телефоне/ТСД.
- Самолёты, спецтехника (GSE), маршруты, блокировка участков.
- Демо-состав смены с вымышленными ФИО — см. [`data/STAFF.md`](data/STAFF.md).

## Запуск

### Desktop-приложение

Приложение для Windows, macOS и Linux использует Tauri 2. Перед сборкой нужны
Rust, Node.js и системные зависимости WebView для Tauri. В режиме разработки:

```bash
python -m pip install -r requirements.txt
npm install
npm run desktop:dev
```

Для установщика с локально встроенным Python-сервисом:

```bash
python -m pip install -r requirements.txt pyinstaller
npm run desktop:build
```

Сборку установщика выполняйте на целевой операционной системе. Приложение
сохраняет SQLite-базу в системной папке данных пользователя. Интерфейс можно
запускать и в браузере; существующие роли и API продолжают работать.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python run.py --airport data/airport_sheremetyevo.json
# открыть http://127.0.0.1:8000
```

3D сразу: <http://127.0.0.1:8000/?view=3d> или `#3d`.
Домодедово: `python run.py --airport data/airport_domodedovo.json`.

### Windows

Скачайте/распакуйте архив и запустите `START-WINDOWS.bat` — он создаст
окружение, установит зависимости и предложит выбрать аэропорт. Подробная
инструкция: [`README-WINDOWS.txt`](README-WINDOWS.txt).

Кнопка **3D/2D** — правый верхний угол карты. В 3D: перетаскивание — поворот,
колесо/пинч — масштаб, двойной клик — вернуться к перрону.

## Настройки сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AIRPORT_FILE` | `data/airport_demo.json` | JSON карты аэропорта |
| `TECHS_FILE` | `data/technicians.json` | демо-состав смены |
| `DB_FILE` | `dispatch.db` | SQLite: заявки, журнал, аккаунты, сессии |
| `DEMO_MODE` | `1` | создавать демо-аккаунты и показывать их на странице входа |
| `DISPATCHER_EMAIL` | — | bootstrap-диспетчер при `DEMO_MODE=0` |
| `DISPATCHER_PASSWORD` | — | пароль bootstrap-диспетчера |
| `DISPATCHER_NAME` | `Диспетчер смены` | имя bootstrap-диспетчера |
| `COOKIE_SECURE` | `0` | `1` — cookie только по HTTPS |

Для закрытого контура без демо-аккаунтов:

```bash
DEMO_MODE=0 \
DISPATCHER_EMAIL=dispatcher@example.ru \
DISPATCHER_PASSWORD='сильный-пароль' \
COOKIE_SECURE=1 \
python run.py --airport data/airport_sheremetyevo.json
```

В этом режиме регистрация инженеров продолжает работать: первый диспетчер
подтверждает заявки вручную.

## Пересобрать карту из OSM

Нужен интернет. Данные © участники OpenStreetMap, лицензия ODbL —
указывайте это в презентации.

```bash
# напрямую с OSM API (работает, когда Overpass перегружен)
python tools/osm_to_airport.py --bbox 37.32,55.96,37.46,55.99 \
    --name "Шереметьево (SVO · UUEE)" --max-stands 18 \
    --out data/airport_sheremetyevo.json

python tools/osm_to_airport.py --bbox 37.86,55.39,37.96,55.43 \
    --name "Домодедово (DME · UUDD)" --max-stands 18 \
    --out data/airport_domodedovo.json

# если уже есть выгрузка OSM XML — без интернета
python tools/osm_to_airport.py --input svo.osm --out data/airport_sheremetyevo.json

# через Overpass по ICAO (если Overpass доступен)
python tools/osm_to_airport.py --icao UUEE --out data/airport_sheremetyevo.json
```

Порядок `--bbox`: `minlon,minlat,maxlon,maxlat` (как у OSM API).
Скрипт собирает мультиполигоны терминалов, поэтому у Домодедово и
Шереметьево на карте есть реальные контуры терминалов.

## Инженеры и допуски

`data/technicians.json` — 9 человек демо-смены. У каждого:

```json
{"name": "Иванов П. С.", "qual": "Планер", "types": ["A320", "B737", "SSJ-100"],
 "speed": 4.0, "base": "BASE1"}
```

`types` — допуски на типы ВС. Если борт на стоянке имеет тип, которого нет
у техника, он не назначается; в таблице кандидатов видно причину
«нет допуска на A350». Для каждой квалификации в демо покрыты все типы
из парка: A320, B737, B777, A330, A350, SSJ-100.

Реальные ФИО сотрудников не публикуются в открытых источниках, поэтому имена
вымышленные. Что нужно уточнить у организаторов/перевозчика — в
[`data/STAFF.md`](data/STAFF.md).

## Тесты

```bash
python -m tests.test_engine
python -m tests.test_auth
```

- `test_engine` — 21 сценарий: подбор по квалификации и ETA, норматив,
  ЧС, занятость, блокировка участков, движение, позиция и профиль инженера,
  пауза/старт и ограничение времени расчёта.
- `test_auth` — 4 сценария: демо-вход, регистрация → подтверждение, отказ,
  уникальность email, постоянный `tech_id`, приватность снапшота инженера,
  сохранение одобренного техника после сброса демо-данных.

Полная сверка продукта и конкурсных критериев находится в
[`docs/Сверка-с-ТЗ.md`](docs/Сверка-с-ТЗ.md). Там отдельно отмечены
ограничения симуляции транспорта, интеграции источников данных, результаты
сценарного сравнения и отсутствующие конкурсные материалы.

## Ограничения прототипа

- GPS и корпоративная телеметрия не подключены. Положение инженеров, ВС и
  машин в прототипе симулируется; реальное положение можно подключить позже.
- Подбор сравнивает пеший маршрут с поездкой на одной из трёх симулируемых
  инженерных машин. Скорость, время посадки и размеры парка требуют настройки
  по подтверждённым данным конкретного аэропорта.
- 3D минимальное: контуры и высоты зданий без текстур и мелкой детализации.
- Парковка и крытые перроны не моделируются.
- Для прототипа нет подтверждения email, восстановления пароля, 2FA,
  ограничения попыток входа и журнала административных действий. Для
  промышленной эксплуатации нужны TLS, внешний identity provider или
  корпоративный SSO, резервное копирование и rate limiting.
- SQLite подходит для одной смены/пилота. Для нескольких площадок и высокой
  нагрузки нужна PostgreSQL и миграции.
